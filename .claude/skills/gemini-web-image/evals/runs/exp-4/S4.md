# S4 — Fill a 3-row manifest while two unrelated Gemini conversations are open

Scope: three `ai` rows, one pass, originals (not the canvas copy). Two Gemini
conversations belonging to the user are already open in the browser and must be
neither read, navigated, moved, nor closed.

Throughout, `<project>` is the project the caller named; every command below uses
the real path
`/Users/jaehyeonroh/Desktop/Personal/slide-master/projects/<project>/images/image_prompts.json`.
Commands are run from the repo root
`/Users/jaehyeonroh/Desktop/Personal/slide-master`.

---

## 0. Why the two open conversations cannot become mine

This is the whole scenario, so I state the mechanism before the commands and
then let every later step be a consequence of it.

1. **Row → tab binding is by session name, not by search.** The bridge scopes its
   "current tab" to the session, so sessions `ppt-master-image-1`, `-2`, `-3`
   (`slot_name()`, `SESSION_PREFIX = "ppt-master-image"`) each own one tab that no
   other session can move. The user's two conversations belong to no
   `ppt-master-image-N` session, so no slot call can reach them.
2. **Each slot tab is created, never adopted.** `submit()` opens the slot with
   `navigate {"url": "https://gemini.google.com/images", "newTab": True}`. A brand
   new tab is made for the row; nothing attaches to a tab that already existed.
3. **`find_tab` is never used.** It returns `"ok": true` without switching tabs,
   and a collection loop built on it once wrote one image under four names. A
   search for "a Gemini tab" is exactly the operation that would match a user
   conversation, so that operation never happens.
4. **The slot number is written down, not inferred.** On success `submit()` sets
   `item["slot"] = i` and the manifest is written immediately. Which tab holds
   which row is that integer — never a URL, a title, or page text, all of which
   the user's conversations also have.
5. **No slot is navigated after submitting.** The tab already holds the finished
   image; re-opening a conversation is what makes it decode slowly or bounce to
   `/app`, and it is also what would let a slot drift onto another tab.
6. **Cleanup targets sessions, not tabs.** `close_tab` is issued per slot session,
   never against a tab id or title taken from `list_tabs`.
7. **A checksum check catches a break after the fact.** If isolation had failed,
   two of my three outputs would be byte-identical.

Additionally, the script's daemon probe runs on the bare prefix session
`ppt-master-image` (`require_daemon()`), which is not `ppt-master-image-1/2/3`, so
that probe can never turn into a row's tab either.

## 1. Preconditions

### 1.1 Manifest — checked first, because it is free and touches no browser

```bash
python3 -c "import json,sys; m=json.load(open('projects/<project>/images/image_prompts.json')); print(json.dumps(m['items'], ensure_ascii=False, indent=2))"
```

What I check and the branch each outcome takes:

| Check | Branch |
|---|---|
| `items` parses and has 3 rows | Continue. If it does not parse, stop: precondition "Valid `image_prompts.json`" failed. |
| At least one row is not `Generated` | Continue. If all three are `Generated`, the script logs `nothing to do` — stop and report there is nothing to fill. |
| Every pending row has `prompt`, `filename`, `aspect_ratio` | Continue. A missing key raises `KeyError` inside `submit()` mid-run; better to catch it here. |
| Every pending row is an `ai` row | Continue. The script selects on `status != "Generated"` only — it does **not** filter by type — so a non-`ai` pending row would be prompted into Gemini. If one exists, I stop and hand it back to the caller rather than generating it. |
| No pending row already carries a `slot` | Expected for a fresh fill. If a stale `slot` is present from an earlier run, I still take the submit path (below), which overwrites `slot` with this pass's index. I do **not** start with `--collect-only`, because a stale slot points at a tab that may no longer exist. |

### 1.2 WebBridge daemon

I do not curl the daemon myself. `require_daemon()` runs before anything else in
`main()` and raises with the exact remediation text if the bridge is silent. If
the run aborts there, I stop and name that precondition; I do not fall back to
another image path — that decision is the caller's.

### 1.3 Gemini signed in, and the browser UI in Korean

These two can only be proven from a live page, and the only pages I am willing to
read are my own. So I prove them from slot 1's freshly opened tab rather than
from either of the user's conversations:

- If `ppt-master-image-1`'s snapshot yields the Korean prompt box
  (`'name': 'Gemini 프롬프트 입력'`), the session is signed in *and* the UI is
  Korean. Both preconditions are satisfied by the first successful submit, and no
  extra tab was spent.
- If instead the log reads `prompt box never appeared for <file>`, the three
  causes are ambiguous by design (loading / signed out / non-Korean UI), and §7 of
  the skill says to read the URL rather than guess. I read it with a bridge
  `evaluate` of `location.href` on session `ppt-master-image-1` only — never
  `find_tab`, never a re-navigation, never a look at the user's tabs.

Because a language or sign-out failure fails all three rows identically, I run
the script in the background and watch the submission log, and if **row 1**
reports `prompt box never appeared` I stop the process before rows 2 and 3 repeat
the same three navigations. Stopping early also keeps me well clear of the
pacing/abuse concern.

### 1.4 Downloads (optional)

I do not change any browser setting. If `gemini.google.com` is allowed under
automatic downloads, rows arrive at original size; if not, the canvas fallback
still completes the run at 1024px. Which one happened is read from the log in
§4, not assumed.

### 1.5 Record the pre-existing tabs (accounting only)

One `list_tabs` on a non-slot session, purely to write down that two Gemini
conversations exist before I start, so that the end-of-run cleanup can be shown
to have left them untouched. **The returned list is never used to select, focus,
or close anything** — selecting a tab from a list is the failure mode this
scenario is about. If I cannot make this call without ambiguity, I skip it; it is
bookkeeping, not a gate.

## 3. The run

```bash
python3 .claude/skills/gemini-web-image/scripts/gemini_web_image.py \
  --manifest projects/<project>/images/image_prompts.json \
  --batch 3
```

Flag decisions:

| Flag | Choice | Why |
|---|---|---|
| `--manifest` | the project's `images/image_prompts.json` | Required. |
| `--output` / `-o` | omitted | Defaults to the manifest's folder, which is the `images/<filename>` contract Step 6 honors. |
| `--batch` | `3` | The whole set goes in one pass; splitting only repeats the submission cost. I pass it explicitly rather than relying on the default because SKILL.md §3 documents the default as `4` while the script's `argparse` default is `10` — either would cover three rows, but `3` makes this pass deterministic regardless of which is live. Three tabs is also far below the ten-tab run that once tripped Google's unusual-traffic challenge. |
| `--generate-wait` | omitted | Script default (10s) is fine; sweeping early costs one cheap probe per slot. (SKILL.md §3 lists 25 for this default; the difference does not change the plan.) |
| `--deadline` | omitted (300s) | Three rows is roughly 30s of submission plus ~36s of serial downloads plus 20–50s of generation — comfortably inside 300s, unlike the ten-row case. |
| `--displayed-size` | **not** passed | I want the originals. The deadline is not tight at three rows, so trading ~12s/row for 1024px buys nothing here. |
| `--collect-only` | **not** passed on this pass | There are no tabs of mine open yet. Collect-only reads `slot` values and sweeps slot sessions; with no submission from this process there is nothing legitimate to collect. |

I run it in the background so the submission lines are visible while they happen
(see §1.3).

## 4. Reading the log, with the branch for each line

Expected shape: `submitting 3 prompt(s), one tab each` → three `submitted <file>
(<ratio>)` lines → `3 submitted in Ns; settling 10s before the first sweep` →
sweeps → three `saved <file> WxH ...` lines → the final tally.

| Log line | What it means | Branch |
|---|---|---|
| `submitted <file> (<ar>)` | The tab reached `/app/<id>` **and** the answer started (`SUBMITTED_JS`: `conv` and `answering`). `slot` is now recorded in the manifest. | Continue. |
| `send did not take for <file>; retrying once` | Send click reported success but the page did not accept it. | The script refills and resends once. No action. |
| `send never took for <file> — leaving it Pending` | Row is Pending with **no** `slot` recorded. | Never collect it. Resubmit it in a later normal (non-`--collect-only`) run. |
| `navigate failed twice for <file>` | Bridge refused the new tab twice. | Same as above — no slot, so resubmit, do not guess a tab. |
| `prompt box never appeared` on row 1 | Ambiguous: still loading / signed out / non-Korean UI / abuse interstitial. | Stop the process. Read `location.href` on session `ppt-master-image-1`. If it is `google.com/sorry/index`, this is Google's unusual-traffic challenge: stop, tell the user, do **not** attempt to answer it; already-generated tabs are unaffected and only new navigations fail. If it is a signed-out Gemini page, report the sign-in precondition. If the page is a normal Gemini page in another UI language, stop and re-read the five accessible-name patterns from that live page before doing anything else — the skill forbids guessing them. |
| `sweep N: K still generating` | Normal. Slots are polled concurrently; a still-generating slot is skipped and revisited. | Wait. Never block on a single slot. |
| `<file>: no answer started — dropping it` | 75s (`DEAD_ROW_GRACE`) with neither an image nor "Creating your image": the conversation opened blank. | The row stays Pending. Note that it still carries its `slot`, so a `--collect-only` rerun would re-sweep that same empty tab — I therefore resubmit it with a normal run (which reassigns `slot`), not with `--collect-only`. |
| `<file>: extraction failed, retrying next sweep` | Image present but not extractable yet. | No action; bounded by the deadline. |
| `original file via the viewer download (Ns)` | The viewer was opened (`OPEN_VIEWER_JS` → the result `<img>`'s enclosing `<button>`), `원본 크기 이미지 다운로드` was found and clicked, a new `~/Downloads/Gemini_Generated_Image_*` landed, size settled, and the file was copied and the extras cleared. This is the good path. | Continue. |
| `viewer download did not produce a file; reading the rendered image instead, and not attempting it again this run` | Downloads are refused by this browser. `_download_refused` is now global, so **all remaining rows** take the canvas copy at 1024px. | Finish the run, then decide with the caller: accept 1024px, or allow `gemini.google.com` under the browser's automatic-downloads setting and re-run the affected rows (set their `status` back so they are re-taken). I do not change that browser setting myself. |
| `saved <file> WxH ratio R vs A (N bytes) [sweep S, read at Ts, gemini done at Gs, lag Ls]` | Row done, `status` → `Generated`, `slot` popped, manifest written immediately. | Check `W`x`H`: 2752x1536 for 16:9 / 2048x2048 for 1:1 indicate originals; 1024-wide indicates the canvas copy. A large `lag` means detection on our side, not Gemini's generation. |
| `** ratio off, review this row` | Drift over 4% from the row's `aspect_ratio`. | That row needs a resubmit, not a footnote. |
| `<file>: not ready before the deadline — left Pending` | Deadline expired. | Tabs are still open and `slot` is still recorded → this is the one case where `--collect-only` is the right rerun (§6). |
| `saved N this run · manifest T/3 · Es elapsed (within/OVER the 300s deadline)` | Final tally. | `OVER`, or `len(slots) != saved`, prints the over-budget note; at three rows this would mean something genuinely went wrong, not a batch-size problem. |

## 5. Verify before reporting success

Run all four; item 3 is the one that proves the S4 property.

1. Every requested row reads `Generated` and its file exists:

```bash
python3 -c "import json,os; m=json.load(open('projects/<project>/images/image_prompts.json')); d='projects/<project>/images'; [print(i['status'], os.path.exists(os.path.join(d,i['filename'])), i['filename']) for i in m['items']]"
```

2. Each file's ratio within 4% of its row's `aspect_ratio` — already asserted by
   the absence of `** ratio off` in the log; the printed `WxH` per row is the
   record.

3. **No two output files share a checksum.** Identical files mean slot isolation
   broke — i.e. two rows read the same tab, which in this scenario is exactly the
   failure "one of the user's conversations got read as mine" would produce. If
   any two match, the run is redone, not patched.

```bash
shasum -a 256 projects/<project>/images/*.png | awk '{print substr($1,1,12), $2}' | sort
```

4. `~/Downloads` holds no leftover `Gemini_Generated_Image_*`:

```bash
ls -la ~/Downloads/Gemini_Generated_Image_* 2>/dev/null || echo "clean"
```

Plus one S4-specific check: the manifest's `Generated` rows must have **no**
residual `slot` key (`collect()` pops it on success), so nothing in the manifest
still points at a tab.

## 6. Reruns, only where they are legitimate

- **Rows left Pending with a recorded `slot`, tabs untouched** (deadline expiry,
  slow generation) — the only case for:

```bash
python3 .claude/skills/gemini-web-image/scripts/gemini_web_image.py \
  --manifest projects/<project>/images/image_prompts.json \
  --collect-only
```

  This reads slots by session name, so it still cannot reach the user's two
  conversations. If the script logs `no recorded slot for <file> … Resubmit them
  instead of collecting`, I resubmit that row — I never invent a slot number, and
  I never renumber survivors (row 3 alone becoming slot 1 is how row 1's image
  gets saved under row 3's name).

- **Rows Pending with no `slot`** (send never took, navigate failed) — a normal
  run, which assigns fresh slots.

- **A dropped-but-slotted row** (`no answer started`) — a normal run, not
  `--collect-only`, because its recorded slot points at a tab that never
  answered.

- **`/sorry/` interstitial** — no rerun at all until the user clears the
  challenge in the browser.

## 7. Cleanup

Only after all three rows read `Generated` (a `--collect-only` rerun needs those
tabs, so nothing is closed before that), I offer:

- `close_tab` on session `ppt-master-image-1`, then `-2`, then `-3`. That removes
  each tab and its `agent:ppt-master-image-N` group.
- Nothing else is closed. I do not close by tab id or title, and I do not act on
  anything `list_tabs` returned — the user's two conversations and their tabs are
  outside every session I own and stay exactly as they were.

If any row is still Pending, I say so and leave all three tabs open.

## 8. Standing prohibitions for this run

- Never `find_tab` — it lies, and it is the one call that could match a user
  conversation.
- Never navigate, reload, or focus a slot after its prompt was submitted.
- Never infer a row's tab from a URL, a title, or page text.
- Never read, snapshot, or evaluate against the two pre-existing conversations.
- Never close a tab that is not one of my three slot sessions.
- Never answer Google's unusual-traffic challenge; stop and hand it to the user.
- Rows this skill cannot finish stay `Pending` and go back to the caller — the
  manifest is the record.
