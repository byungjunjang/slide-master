## Problem

Image generation through the `agy` backend stopped after 11 images and refused
every later call, while Antigravity's Models & Usage panel reported 99% of the
weekly Gemini limit and 93% of the five-hour limit still remaining. Reading the
panel as authoritative led to the wrong diagnosis twice: first "the subscription
allowance is spent", then "concurrent sessions are being rate-limited".

## Solution

A single-image probe with no concurrency was still refused, which ruled out
burst rate-limiting. The image path therefore has its own allowance that the
usage panel does not report.

Measured 2026-08-19: 11 successful generations over ~22 minutes, then sustained
refusal. Success rate before the wall was 11 of 11 — the CLI does not drop calls.

Operating rule now written into
`.claude/skills/ppt-master/references/image-generator.md`: cap a manifest pass at
8 `ai` rows and keep the remaining 2-3 of the window for re-rolls. Rows beyond
that stay `Pending` and re-run after the allowance resets, since the manifest is
idempotent.

Detecting the refusal needs care. The CLI announces it as model-written prose on
stdout with exit code `0`, an empty stderr, and no error line in its log. The
wording varies between runs — both "the model's capacity has been exhausted ...
once your quota resets" and "I encountered a quota exhaustion error" appeared the
same day — so the matcher stays broad and runs per line, because the CLI's
internal log mentions `quota_manager` and `doRefreshQuota` during healthy runs.

## Key Insight

A vendor's usage dashboard can be silent about the specific capability you are
consuming. When a limit contradicts the dashboard, isolate the variable with the
smallest possible request rather than trusting either reading.

Raising concurrency does not help when the binding constraint is an allowance
rather than wall time — more workers reach the same wall sooner.

## Context

The reset window is still unmeasured; "8 per pass" is derived from an observed
ceiling of 11, not a documented limit. Full measurement record:
