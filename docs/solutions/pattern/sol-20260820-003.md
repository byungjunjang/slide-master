## Problem

Two verification devices were found in one session to have never fired once, and
both had been reported as working.

**The eval check that could not match.** The gemini-web-image suite's B1 asks
whether a plan calls `find_tab`, the bridge action that reports success without
switching tabs. Its scorer flattened markdown emphasis with `[*`_]+` before
searching — which also removed underscores, turning `find_tab` into `findtab`
everywhere in the text it searched. The needle could never appear, `hits` was
always empty, and the function's first line reads:

```python
if not hits:
    return True
```

So every plan passed B1 for free, across five experiments and three earlier
calibration rounds. The check was reported as passing in every score ever taken.
It surfaced only when underscores were preserved for an unrelated reason and
three plans failed on the same run — which is what a live check looks like.

**The probe whose condition is never true.** A two-clock readiness probe was
added the same week to separate Gemini's clock (`finished`) from ours
(`decoded`), so a slow row could be attributed to the right side. Across a clean
ten-row run it printed no lag note at all. `finished = present && !creating`,
and the page keeps "Creating your image" in the DOM past the point the image is
readable — so `finished` is still false when `decoded` turns true, on every
healthy row. The instrument built to prevent a specific misattribution has never
produced a reading.

Both were believed to work for the same reason: nothing they emit was ever
missed, because they emit nothing.

## Solution

Make each instrument fail once, deliberately, before trusting a pass.

- **A checker earns trust by rejecting something.** Feed it input that must
  fail. If a check has never rejected anything across its whole history, that is
  the finding — not the score it produced.
- **A probe earns trust by changing state.** Confirm the reported field actually
  flips on a real run. "The code path exists" and "the branch is reachable" are
  different claims, and only the second is evidence.
- Record the retraction where the claim lives. The skill's timing section now
  says the lag note has never printed and must not be leaned on until it does.

## Key Insight

A check that cannot fail and a check that passes produce the same observation.
Only a deliberate failure separates them.

The corollary is about absence: a missing warning is evidence only if that
warning has been seen at least once. Every "no errors" and every "no lag
reported" in this project was, for one check and one probe, the sound of an
instrument that was never plugged in.

The failure is likeliest right where confidence is highest — an instrument added
*as the fix* for an earlier mistake is rarely re-verified, because the lesson it
encodes already feels learned.

## Context

Measured on `.claude/skills/gemini-web-image/evals/score.py` (B1, dead since the
suite was written) and `gemini_web_image.py` `READY_JS` (the `finished` clock,
across a 10/10 live run on 2026-08-20). Both faults were found by side effects
of other work, not by anything watching for them.
