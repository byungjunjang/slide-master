## Problem

The gemini-web-image skill carried this rule, because the Gemini page exposes no
aspect-ratio control and the ratio has to travel inside the prompt:

> Put the ratio in the prompt's first line.

Read as written, that is an instruction to whoever writes the manifest. So the
manifest was written with the line in it. `submit()` also prepended
`RATIO_PREFIX` from the row's own `aspect_ratio`, because the same rule read as
an instruction to the code. Both parties obeyed correctly, and every prompt
reached the page with the sentence twice:

```
Generate a 1:1 image (aspect ratio exactly 1:1).

Generate a 1:1 image (aspect ratio exactly 1:1).

Strict Swiss-grid minimalism. …
```

Ten rows shipped that way. Nothing in the project could see it: the images came
back at the right ratios, the manifest validated, the ratio check compared
pixels rather than prompts, and the quality checker never reads prompt text at
all. It was caught by the user opening the conversation in the browser and
reading what had actually been sent.

The duplication was invisible *because* both sides were right. A contradiction
would have surfaced; agreement did not.

## Solution

Rewrite the rule so it names its executor and forbids the other party:

> The ratio rides in the prompt's first line, and the script puts it there.
> **The manifest's `prompt` must not carry that line itself.**

Then make the code idempotent rather than merely obedient — and make the one
case that is genuinely a manifest error loud instead of silently doubling it:

```python
lead = RATIO_PREFIX.format(ar=ratio)
if prompt.lstrip().startswith(lead.strip()):
    return prompt
stale = RATIO_LINE_RE.match(prompt.lstrip())
if stale and stale.group(1) != ratio:
    log(f"  ** prompt opens with a {stale.group(1)} ratio line but the row "
        f"asks for {ratio}; sending the row's ratio in front of it")
return lead + prompt
```

## Key Insight

A rule addressed to nobody in particular is executed by everyone who reads it.
When a contract is shared between a document and the code that document
describes, the sentence has to say which one performs it — "put X in Y" is an
instruction to both.

Duplication of this shape is unusually durable because every local check passes.
Look for it wherever a doc sentence and a code path implement the same
requirement, and prefer making the executing side idempotent, so a second
well-meaning party cannot double the effect.
