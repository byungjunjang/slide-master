## Problem

`backend_agy.py` decided whether the Antigravity CLI had generated an image by
searching the conversation transcript for the literal string
`"type": "GENERATE_IMAGE"`. The CLI labels that same tool-result step
`GENERATE_IMAGE` in some runs and the unspecific `GENERIC` in others — the
`GENERIC` shape appears when a `CHECKPOINT` lands at the head of the
conversation. Every `GENERIC` run was declared a failure even though the image
sat finished on disk, and the adapter then re-ran the whole session up to three
times, discarding a fresh image each time.

The symptom read as "agy cannot generate multiple images". It was neither a
generation failure nor a concurrency failure: it was a recovery failure that
scaled with the number of images requested.

## Solution

Parse the transcript as JSON Lines and key on evidence the CLI cannot relabel:

- a recorded `tool_calls` entry whose `name` is `generate_image` (a raw text
  search also matches the tool inventory the CLI pastes into every conversation,
  so the record must be parsed, not grepped)
- the tool's own closing sentence, `Generated image is saved at <path>`

The reported path then becomes the only file the adapter accepts, confined to
that conversation's own directory. The previous modification-time directory scan
was removed: across 505 archived conversations, all 135 that held an image also
named it in the transcript, so the scan added nothing — and it was the only route
through which a script-written stand-in could have been accepted.

Regression check: 135/135 correct recovery, zero false rejections, zero phantom
acceptances.

## Key Insight

A label an external tool assigns to its own step is presentation, not contract.
Verify a subprocess by the action it recorded and the artifact it named, and
prefer an exact path the tool stated over any heuristic that ranks files by
timestamp.

The second-order cost matters more than the first: a false-failure verdict feeds
a retry loop, and each retry silently consumed a scarce upstream allowance while
producing nothing. Before adding retries to a step, confirm the failure detector
is right — a wrong detector turns retries into an amplifier.
